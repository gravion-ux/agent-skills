# Generate headline options and subheadings that fit the platform and the reader's benefit

## Purpose

Generate headline options and subheadings that fit the platform and the reader's benefit.

## When to use

Use when the user needs titles and section headings for a piece.

## When NOT to use

Do not use this for internal engineering documentation; use technical-writing instead.

## Inputs required

- The platform and the format
- The audience and the tone
- The source material, the hook and the call to action

## Procedure

1. Name the reader's main benefit and the piece's core claim.
2. Draft five headline options across literal, curiosity and benefit angles.
3. Check each option against the platform's character limit and house style.
4. Write subheadings that advance the argument instead of restating the title.
5. Return the options with a one-line rationale for the recommended choice.

## Output contract

A publishable draft in the target format, with a title, hook, body and close.

## Validation checklist

- [ ] The opening earns the next sentence
- [ ] The draft matches the platform's format and length
- [ ] Every factual claim is sourced

## Safety notes

Never publish without approval, and never present generated statistics as real data.
