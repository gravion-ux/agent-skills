# Define domain terms consistently with usage examples and links to deeper explanations

## Purpose

Define domain terms consistently with usage examples and links to deeper explanations.

## When to use

Use when the user wants a glossary that standardizes vocabulary across product documentation.

## When NOT to use

Do not use this for a persuasive article or campaign copy; use content-creation instead.

## Inputs required

- The audience and what they must be able to do
- The subject and the source material
- The format and the maintenance owner

## Procedure

1. Collect terms from the source material and recurring reader questions.
2. Define each term in one sentence with the system's actual meaning.
3. Add a usage example or a link to a fuller explanation.
4. Expand unfamiliar abbreviations on first use throughout the guide.
5. Have the subject owner verify every definition.

## Output contract

A document that answers the reader's question, with structure, examples and an owner.

## Validation checklist

- [ ] The document answers its stated question
- [ ] Examples are runnable and current
- [ ] Every claim can be traced to a source

## Safety notes

Never document a command you have not run, and never leave an internal secret in an example.
