# Explain the product's core ideas with a concrete model and minimal jargon

## Purpose

Explain the product's core ideas with a concrete model and minimal jargon.

## When to use

Use when the user needs a conceptual explanation of how a product or subsystem works.

## When NOT to use

Do not use this for a persuasive article or campaign copy; use content-creation instead.

## Inputs required

- The audience and what they must be able to do
- The subject and the source material
- The format and the maintenance owner

## Procedure

1. State the reader's question and the concept being explained.
2. Define the essential terms before using them in the model.
3. Build a concrete mental model from the system's real components.
4. Connect the model to one observable product behavior.
5. Cite the authoritative source for each technical claim.

## Output contract

A document that answers the reader's question, with structure, examples and an owner.

## Validation checklist

- [ ] The document answers its stated question
- [ ] Examples are runnable and current
- [ ] Every claim can be traced to a source

## Safety notes

Never document a command you have not run, and never leave an internal secret in an example.
