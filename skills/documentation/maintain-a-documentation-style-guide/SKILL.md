# Maintain writing rules and examples that keep documentation consistent across contributors

## Purpose

Maintain writing rules and examples that keep documentation consistent across contributors.

## When to use

Use when the user wants to establish or update the shared writing rules for a documentation set.

## When NOT to use

Do not use this for a persuasive article or campaign copy; use content-creation instead.

## Inputs required

- The audience and what they must be able to do
- The subject and the source material
- The format and the maintenance owner

## Procedure

1. Inventory recurring style problems in representative published documents.
2. Define actionable rules for terminology, structure, tone, and formatting.
3. Pair each rule with a short before-and-after example.
4. Assign an owner for exceptions, questions, and rule changes.
5. Review the guide against recent content and record needed updates.

## Output contract

A document that answers the reader's question, with structure, examples and an owner.

## Validation checklist

- [ ] The document answers its stated question
- [ ] Examples are runnable and current
- [ ] Every claim can be traced to a source

## Safety notes

Never document a command you have not run, and never leave an internal secret in an example.
