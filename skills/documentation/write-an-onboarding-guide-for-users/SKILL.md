# Give a new user a day-one path to value with roles, tasks, and support checkpoints

## Purpose

Give a new user a day-one path to value with roles, tasks, and support checkpoints.

## When to use

Use when the user wants an onboarding guide that helps new users reach an early success.

## When NOT to use

Do not use this for a persuasive article or campaign copy; use content-creation instead.

## Inputs required

- The audience and what they must be able to do
- The subject and the source material
- The format and the maintenance owner

## Procedure

1. Define the first valuable outcome for each user role.
2. Order onboarding tasks around prerequisites and access needs.
3. Add a clear checkpoint and expected result to each task.
4. Name the support route for blocked steps.
5. Assign an owner to review the guide as the product changes.

## Output contract

A document that answers the reader's question, with structure, examples and an owner.

## Validation checklist

- [ ] The document answers its stated question
- [ ] Examples are runnable and current
- [ ] Every claim can be traced to a source

## Safety notes

Never document a command you have not run, and never leave an internal secret in an example.
