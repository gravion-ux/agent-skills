# Plan documentation sites around user tasks, ownership, navigation, and maintenance cycles

## Purpose

Plan documentation sites around user tasks, ownership, navigation, and maintenance cycles.

## When to use

Use when the user wants a plan for organizing and maintaining a documentation set.

## When NOT to use

Do not use this for a persuasive article or campaign copy; use content-creation instead.

## Inputs required

- The audience and what they must be able to do
- The subject and the source material
- The format and the maintenance owner

## Procedure

1. Inventory audiences, recurring questions, and source materials.
2. Map each question to a durable content type and canonical location.
3. Define templates, navigation rules, and ownership for every section.
4. Identify gaps, duplication, and content that needs consolidation.
5. Schedule a review cycle and assign owners for each content type.

## Output contract

A document that answers the reader's question, with structure, examples and an owner.

## Validation checklist

- [ ] The document answers its stated question
- [ ] Examples are runnable and current
- [ ] Every claim can be traced to a source

## Safety notes

Never document a command you have not run, and never leave an internal secret in an example.
