# Build a tutorial whose every step has been executed and confirmed in order

## Purpose

Build a tutorial whose every step has been executed and confirmed in order.

## When to use

Use when the user wants a tutorial that readers can complete without undocumented gaps.

## When NOT to use

Do not use this for a persuasive article or campaign copy; use content-creation instead.

## Inputs required

- The audience and what they must be able to do
- The subject and the source material
- The format and the maintenance owner

## Procedure

1. Choose a concrete outcome that exercises the main workflow.
2. Draft the steps from the verified source workflow.
3. Execute every step in a clean environment without skipping checks.
4. Capture the expected output for each observable change.
5. Review the tutorial from a new reader's starting point.

## Output contract

A document that answers the reader's question, with structure, examples and an owner.

## Validation checklist

- [ ] The document answers its stated question
- [ ] Examples are runnable and current
- [ ] Every claim can be traced to a source

## Safety notes

Never document a command you have not run, and never leave an internal secret in an example.
