# Plan a screencast by scripting each screen change, the narration and the zoom level

## Purpose

Plan a screencast by scripting each screen change, the narration and the zoom level.

## When to use

Use when the user wants to record a software walkthrough.

## When NOT to use

Do not use this for a still image; use image-visual instead.

## Inputs required

- The source material and the target duration
- The format, the channels and the captions
- The rights and the music licensing constraints

## Procedure

1. List the tasks the viewer should be able to do after watching.
2. Write the order of the screens and the state each one starts in.
3. Mark the cursor movement and the zoom level for the important moments.
4. Write the narration line for each screen change.
5. Reset the test data before the recording so the state is reproducible.

## Output contract

An edited audio or video file with a transcript or caption track and the source list.

## Validation checklist

- [ ] The audio is intelligible at normal volume
- [ ] Captions or a transcript are attached
- [ ] Every clip is licensed

## Safety notes

Never publish audio or footage of a person without consent, and never strip attribution from licensed media.
