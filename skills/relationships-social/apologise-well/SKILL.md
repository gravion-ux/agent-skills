# Apologise in a way that names the harm, takes responsibility and moves forward

## Purpose

Apologise in a way that names the harm, takes responsibility and moves forward.

## When to use

Use when the user has done something that needs a real apology rather than an excuse.

## When NOT to use

Do not use this for a workplace conflict that needs a formal process; use communication or business-ops instead.

## Inputs required

- The situation and the relationship
- What the user wants to happen next
- The tone and the boundaries that apply

## Procedure

1. Name the specific thing that went wrong without softening it into vagueness.
2. Describe the impact on the other person rather than on the user's intent.
3. Take responsibility directly, with no condition attached to the apology.
4. State what will change so the apology is not only words.
5. Offer to make it right and then let the other person decide.

## Output contract

A suggested approach with wording the user can adapt, plus the outcome to watch for.

## Validation checklist

- [ ] The tone matches the relationship
- [ ] The ask is reasonable and specific
- [ ] The user can edit before sending

## Safety notes

Never send the message without approval, and never advise on a situation where the user is at risk of harm.
