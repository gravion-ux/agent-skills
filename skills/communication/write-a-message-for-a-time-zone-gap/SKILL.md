# Write a message that works for a recipient in a different time zone without being vague

## Purpose

Write a message that works for a recipient in a different time zone without being vague.

## When to use

Use when the user needs to send something to someone they cannot reach synchronously.

## When NOT to use

Do not use this for formal published documentation; use technical-writing instead.

## Inputs required

- The audience and their prior knowledge
- The message and the outcome wanted
- The channel and the deadline

## Procedure

1. Put the key information in the message so nothing depends on being online at the same time.
2. State the deadline with both the date and the time zone.
3. Make it clear that a response is not needed unless it is, and say which.
4. Keep the question, if there is one, to one that can be answered in a line.
5. Do not expect an immediate reply and plan the follow-up accordingly.

## Output contract

A message ready to send, with the ask, the context and the next step made explicit.

## Validation checklist

- [ ] The ask is stated in one sentence
- [ ] The tone matches the audience and channel
- [ ] The next step and its owner are clear

## Safety notes

Never send a message on the user's behalf without explicit approval of the final text.
