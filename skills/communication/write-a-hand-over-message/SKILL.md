# Write a hand-over message that lets the next person continue the work without asking anything

## Purpose

Write a hand-over message that lets the next person continue the work without asking anything.

## When to use

Use when the user is passing a piece of work to someone else.

## When NOT to use

Do not use this for formal published documentation; use technical-writing instead.

## Inputs required

- The audience and their prior knowledge
- The message and the outcome wanted
- The channel and the deadline

## Procedure

1. State where the work stands right now, in one sentence.
2. List what has been done and what is outstanding, with the state of each.
3. List the decisions already made and the constraints that shaped them.
4. Name the people involved and who holds the open questions.
5. Set the date of the next check-in and what should happen at it.

## Output contract

A message ready to send, with the ask, the context and the next step made explicit.

## Validation checklist

- [ ] The ask is stated in one sentence
- [ ] The tone matches the audience and channel
- [ ] The next step and its owner are clear

## Safety notes

Never send a message on the user's behalf without explicit approval of the final text.
