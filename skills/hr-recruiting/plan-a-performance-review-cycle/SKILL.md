# Plan a performance review cycle with clear expectations, fair inputs and time for feedback

## Purpose

Plan a performance review cycle with clear expectations, fair inputs and time for feedback.

## When to use

Use when the user wants to organise a performance review cycle for a team.

## When NOT to use

Do not use this for an onboarding checklist for an existing employee; use business-ops instead.

## Inputs required

- The role, the team and the hiring stage
- The candidate material in scope
- The evaluation criteria and the decision timeline

## Procedure

1. Set the expectations in writing at the start of the cycle, not at the review.
2. Define the rating scale and the evidence that supports each level.
3. Collect the input from a defined set of people for each person reviewed.
4. Schedule the conversations with enough gap between them and the deadline.
5. Write the outcome and the development actions with a date for each.

## Output contract

A structured evaluation or hiring artefact that applies the stated criteria consistently.

## Validation checklist

- [ ] Every criterion is applied to every candidate
- [ ] The decision is traceable to the criteria
- [ ] Personal data is limited to what the process needs

## Safety notes

Never make a hiring decision without human review, and never infer protected attributes from a CV.
