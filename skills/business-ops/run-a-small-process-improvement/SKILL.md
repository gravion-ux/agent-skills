# Run a small process improvement by baselining a metric, testing a change, and checking results

## Purpose

Run a small process improvement by baselining a metric, testing a change, and checking results.

## When to use

Use when the user wants to improve one practical process without launching a large redesign.

## When NOT to use

Do not use this for a single customer conversation; use communication instead.

## Inputs required

- The process being run
- The inputs and who supplies them
- The service level the process must meet

## Procedure

1. Select one process, a pain point, an owner, and a baseline metric with a target.
2. Observe the current steps and capture failures, delays, and workarounds.
3. Propose the smallest change that can be tested within the available time box.
4. Pilot the change on a limited workload and log inputs, exceptions, and results.
5. Compare the pilot metric with the baseline and check for unintended effects.
6. Adopt, revise, or revert the change and document the updated procedure.

## Output contract

A documented operating procedure with owners, inputs, steps and the metrics it is judged on.

## Validation checklist

- [ ] Every step has an owner
- [ ] The failure path is documented
- [ ] The metric that proves the process works is named

## Safety notes

Never change a financial, legal or contractual step without the owner's approval.
