# Map a process from trigger to completion with handoffs, decisions, and time costs

## Purpose

Map a process from trigger to completion with handoffs, decisions, and time costs.

## When to use

Use when the user needs an end-to-end view of how work moves through a process.

## When NOT to use

Do not use this for a single customer conversation; use communication instead.

## Inputs required

- The process being run
- The inputs and who supplies them
- The service level the process must meet

## Procedure

1. Set the start event and end condition for the process boundary.
2. Order each activity and record the role that performs it.
3. Map every handoff with its input, output, and decision rule.
4. Measure or estimate elapsed time and active work at each stage.
5. Mark waiting time, rework loops, and missing ownership in the final map.
6. Annotate the map with the metric that reveals overall process performance.

## Output contract

A documented operating procedure with owners, inputs, steps and the metrics it is judged on.

## Validation checklist

- [ ] Every step has an owner
- [ ] The failure path is documented
- [ ] The metric that proves the process works is named

## Safety notes

Never change a financial, legal or contractual step without the owner's approval.
