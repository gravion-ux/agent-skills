# Run a workstream retrospective to identify causes, corrective actions, and measurable follow-through

## Purpose

Run a workstream retrospective to identify causes, corrective actions, and measurable follow-through.

## When to use

Use when the user wants to improve how a completed or paused workstream ran.

## When NOT to use

Do not use this for a single customer conversation; use communication instead.

## Inputs required

- The process being run
- The inputs and who supplies them
- The service level the process must meet

## Procedure

1. Gather outcome metrics, incident records, and feedback from the workstream participants.
2. Reconstruct the timeline and separate contributing factors from one root cause.
3. Select no more than three corrective actions and name an owner for each.
4. Define a target metric and review date for each corrective action.
5. Document what will change in the next workstream and close the retrospective.

## Output contract

A documented operating procedure with owners, inputs, steps and the metrics it is judged on.

## Validation checklist

- [ ] Every step has an owner
- [ ] The failure path is documented
- [ ] The metric that proves the process works is named

## Safety notes

Never change a financial, legal or contractual step without the owner's approval.
