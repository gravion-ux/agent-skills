# Prioritize a task backlog using urgency, impact, dependencies, and available capacity

## Purpose

Prioritize a task backlog using urgency, impact, dependencies, and available capacity.

## When to use

Use when the user needs to order a backlog into a defensible next set of work.

## When NOT to use

Do not use this for a single customer conversation; use communication instead.

## Inputs required

- The process being run
- The inputs and who supplies them
- The service level the process must meet

## Procedure

1. Collect each task's requester, deadline, impact, effort, and dependencies.
2. Flag tasks blocked by another item and record the blocking owner.
3. Rank tasks by impact and urgency after removing blocked work from the first wave.
4. Match the top wave to the team's available capacity and record the cutoff.
5. Publish the ordered backlog with the metric that will review each priority decision.

## Output contract

A documented operating procedure with owners, inputs, steps and the metrics it is judged on.

## Validation checklist

- [ ] Every step has an owner
- [ ] The failure path is documented
- [ ] The metric that proves the process works is named

## Safety notes

Never change a financial, legal or contractual step without the owner's approval.
