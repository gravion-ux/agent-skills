# Report a blocked task with impact, attempted remedies, owner, and a dated recovery path

## Purpose

Report a blocked task with impact, attempted remedies, owner, and a dated recovery path.

## When to use

Use when the user needs to communicate the status and impact of blocked work.

## When NOT to use

Do not use this for a single customer conversation; use communication instead.

## Inputs required

- The process being run
- The inputs and who supplies them
- The service level the process must meet

## Procedure

1. Describe the expected result and the precise point where progress stopped.
2. List the remedies attempted and the evidence that each did not work.
3. Quantify schedule, cost, customer, or compliance impact.
4. Name the decision owner and the next action with its deadline.
5. Publish the status and set a recovery checkpoint tied to the affected metric.

## Output contract

A documented operating procedure with owners, inputs, steps and the metrics it is judged on.

## Validation checklist

- [ ] Every step has an owner
- [ ] The failure path is documented
- [ ] The metric that proves the process works is named

## Safety notes

Never change a financial, legal or contractual step without the owner's approval.
