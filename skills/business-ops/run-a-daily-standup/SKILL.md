# Run a daily standup with consistent updates, blockers, and assigned follow-ups

## Purpose

Run a daily standup with consistent updates, blockers, and assigned follow-ups.

## When to use

Use when the user needs to run a recurring team status meeting.

## When NOT to use

Do not use this for a single customer conversation; use communication instead.

## Inputs required

- The process being run
- The inputs and who supplies them
- The service level the process must meet

## Procedure

1. List the meeting attendees and assign a facilitator and note-taker.
2. Ask each attendee to report progress, next work, and blockers.
3. Record every blocker beside an owner and a resolution due time.
4. Confirm the next owner and action for each unresolved item.
5. Publish the decisions and follow-ups to the team.
6. Report the carried-over blocker count to measure follow-through.

## Output contract

A documented operating procedure with owners, inputs, steps and the metrics it is judged on.

## Validation checklist

- [ ] Every step has an owner
- [ ] The failure path is documented
- [ ] The metric that proves the process works is named

## Safety notes

Never change a financial, legal or contractual step without the owner's approval.
