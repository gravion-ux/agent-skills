# Write a standard operating procedure with repeatable steps, controls, and escalation rules

## Purpose

Write a standard operating procedure with repeatable steps, controls, and escalation rules.

## When to use

Use when the user needs a consistent procedure others can execute without improvisation.

## When NOT to use

Do not use this for a single customer conversation; use communication instead.

## Inputs required

- The process being run
- The inputs and who supplies them
- The service level the process must meet

## Procedure

1. Define the procedure's scope, trigger, owner, and required service level.
2. Write each step as an instruction, input, action, and expected output.
3. Specify control points and approval requirements for sensitive changes.
4. Add the failure path, owner, and deadline for escalation.
5. Test the draft with a user and attach the metric used to judge compliance.

## Output contract

A documented operating procedure with owners, inputs, steps and the metrics it is judged on.

## Validation checklist

- [ ] Every step has an owner
- [ ] The failure path is documented
- [ ] The metric that proves the process works is named

## Safety notes

Never change a financial, legal or contractual step without the owner's approval.
