# Build a focused weekly plan with capacity limits, priority work, and protected time

## Purpose

Build a focused weekly plan with capacity limits, priority work, and protected time.

## When to use

Use when the user needs to schedule a week's work around priorities and capacity.

## When NOT to use

Do not use this for a single customer conversation; use communication instead.

## Inputs required

- The process being run
- The inputs and who supplies them
- The service level the process must meet

## Procedure

1. List committed outcomes and reserve capacity for routine operational work.
2. Estimate each priority task against the team's available hours.
3. Sequence tasks around dependencies and hard deadlines.
4. Assign an owner and a measurable definition of done to each work block.
5. Publish the plan with its completion metric and any displaced work.

## Output contract

A documented operating procedure with owners, inputs, steps and the metrics it is judged on.

## Validation checklist

- [ ] Every step has an owner
- [ ] The failure path is documented
- [ ] The metric that proves the process works is named

## Safety notes

Never change a financial, legal or contractual step without the owner's approval.
