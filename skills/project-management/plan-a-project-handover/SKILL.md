# Plan a project handover that transfers knowledge, open work, ownership, and acceptance criteria

## Purpose

Plan a project handover that transfers knowledge, open work, ownership, and acceptance criteria.

## When to use

Use when the user needs to transfer an active project to a new owner or team.

## When NOT to use

Do not use this for the technical design of the work; use architecture-design instead.

## Inputs required

- The goal, deadline and constraints
- The people and their capacity
- The dependencies outside the team's control

## Procedure

1. Inventory delivered artefacts, open tasks, decisions, risks, and dependencies.
2. Map each open item to its current owner, next action, and due date.
3. Document operating procedures, access needs, and acceptance criteria.
4. Schedule knowledge-transfer sessions with both outgoing and incoming owners.
5. Confirm the incoming owner accepts each transfer and the next reporting date.

## Output contract

A plan with milestones, owners, dependencies, risks and a status view that stays true.

## Validation checklist

- [ ] Every task has one owner
- [ ] Dependencies and blockers are visible
- [ ] The plan reflects actual status, not the original estimate

## Safety notes

Never report progress that is not backed by delivered work.
