# Run a project kickoff that aligns outcomes, scope, owners, milestones, dependencies, and working agreements

## Purpose

Run a project kickoff that aligns outcomes, scope, owners, milestones, dependencies, and working agreements.

## When to use

Use when the user needs to start a project with a cross-functional team.

## When NOT to use

Do not use this for the technical design of the work; use architecture-design instead.

## Inputs required

- The goal, deadline and constraints
- The people and their capacity
- The dependencies outside the team's control

## Procedure

1. Share the agenda, project goals, constraints, and decision authority before the meeting.
2. Confirm scope, success criteria, milestones, and external dependencies.
3. Assign one accountable owner to each workstream and near-term task.
4. Review risks, assumptions, communication cadence, and escalation paths.
5. Publish decisions, owners, target dates, and the next milestone checkpoint.

## Output contract

A plan with milestones, owners, dependencies, risks and a status view that stays true.

## Validation checklist

- [ ] Every task has one owner
- [ ] Dependencies and blockers are visible
- [ ] The plan reflects actual status, not the original estimate

## Safety notes

Never report progress that is not backed by delivered work.
