# Create an actionable project plan linking milestones, owners, dependencies, risks, and acceptance criteria

## Purpose

Create an actionable project plan linking milestones, owners, dependencies, risks, and acceptance criteria.

## When to use

Use when the user needs a shared plan for delivering a defined project outcome.

## When NOT to use

Do not use this for the technical design of the work; use architecture-design instead.

## Inputs required

- The goal, deadline and constraints
- The people and their capacity
- The dependencies outside the team's control

## Procedure

1. State the goal, deadline, constraints, and evidence required for acceptance.
2. Define milestones with deliverables, named owners, and target dates.
3. Map dependencies and assign owners to every follow-up task.
4. Record risks, assumptions, and the trigger for each mitigation action.
5. Publish the plan and schedule a status review for the next decision point.

## Output contract

A plan with milestones, owners, dependencies, risks and a status view that stays true.

## Validation checklist

- [ ] Every task has one owner
- [ ] Dependencies and blockers are visible
- [ ] The plan reflects actual status, not the original estimate

## Safety notes

Never report progress that is not backed by delivered work.
