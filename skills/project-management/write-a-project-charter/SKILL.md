# Write a project charter that authorizes the work and defines its boundaries, outcomes, owners, and measures

## Purpose

Write a project charter that authorizes the work and defines its boundaries, outcomes, owners, and measures.

## When to use

Use when the user needs agreement on a project's purpose, scope, authority, and success measures.

## When NOT to use

Do not use this for the technical design of the work; use architecture-design instead.

## Inputs required

- The goal, deadline and constraints
- The people and their capacity
- The dependencies outside the team's control

## Procedure

1. State the business goal, problem, desired outcomes, and measurable success criteria.
2. Define in-scope work, exclusions, assumptions, constraints, and key risks.
3. Name the sponsor, project owner, decision maker, and core delivery team.
4. Set the budget, deadline, milestones, and approval authority.
5. Obtain sponsor approval and distribute the charter to stakeholders.

## Output contract

A plan with milestones, owners, dependencies, risks and a status view that stays true.

## Validation checklist

- [ ] Every task has one owner
- [ ] Dependencies and blockers are visible
- [ ] The plan reflects actual status, not the original estimate

## Safety notes

Never report progress that is not backed by delivered work.
