# Run a sprint planning session that converts prioritized backlog items into owned, sized commitments

## Purpose

Run a sprint planning session that converts prioritized backlog items into owned, sized commitments.

## When to use

Use when the user needs to plan an upcoming sprint using an ordered and estimated backlog.

## When NOT to use

Do not use this for the technical design of the work; use architecture-design instead.

## Inputs required

- The goal, deadline and constraints
- The people and their capacity
- The dependencies outside the team's control

## Procedure

1. Confirm the sprint goal, team capacity, constraints, and carryover items.
2. Select the highest-priority backlog items that fit available capacity.
3. Review estimates, dependencies, and acceptance criteria for each selected item.
4. Assign one owner and a sprint target date to every selected item.
5. Publish the committed scope and record excluded items for later planning.

## Output contract

A plan with milestones, owners, dependencies, risks and a status view that stays true.

## Validation checklist

- [ ] Every task has one owner
- [ ] Dependencies and blockers are visible
- [ ] The plan reflects actual status, not the original estimate

## Safety notes

Never report progress that is not backed by delivered work.
