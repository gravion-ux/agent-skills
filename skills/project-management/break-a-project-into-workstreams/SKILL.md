# Partition a project goal into coordinated workstreams with clear interfaces and deliverables

## Purpose

Partition a project goal into coordinated workstreams with clear interfaces and deliverables.

## When to use

Use when the user needs to divide a cross-functional project into manageable workstreams.

## When NOT to use

Do not use this for the technical design of the work; use architecture-design instead.

## Inputs required

- The goal, deadline and constraints
- The people and their capacity
- The dependencies outside the team's control

## Procedure

1. List the goal, deadline, constraints, and people contributing to each deliverable.
2. Group related deliverables into workstreams that can progress with minimal handoffs.
3. Define each workstream's owner, outputs, dependencies, and exit criterion.
4. Name the decisions or approvals required between workstreams.
5. Review the partition with all owners and record unresolved dependencies.

## Output contract

A plan with milestones, owners, dependencies, risks and a status view that stays true.

## Validation checklist

- [ ] Every task has one owner
- [ ] Dependencies and blockers are visible
- [ ] The plan reflects actual status, not the original estimate

## Safety notes

Never report progress that is not backed by delivered work.
