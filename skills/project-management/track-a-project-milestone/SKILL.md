# Track a project milestone against committed deliverables, blockers, and recovery actions

## Purpose

Track a project milestone against committed deliverables, blockers, and recovery actions.

## When to use

Use when the user needs to assess whether a specific project milestone is on track.

## When NOT to use

Do not use this for the technical design of the work; use architecture-design instead.

## Inputs required

- The goal, deadline and constraints
- The people and their capacity
- The dependencies outside the team's control

## Procedure

1. List the milestone deliverables and the evidence required to mark each complete.
2. Verify completion using delivered work rather than status claims.
3. Record blockers, owners, and the next action for each unresolved item.
4. Compare actual progress with the committed milestone date.
5. Choose and record recovery actions when the milestone is at risk.

## Output contract

A plan with milestones, owners, dependencies, risks and a status view that stays true.

## Validation checklist

- [ ] Every task has one owner
- [ ] Dependencies and blockers are visible
- [ ] The plan reflects actual status, not the original estimate

## Safety notes

Never report progress that is not backed by delivered work.
