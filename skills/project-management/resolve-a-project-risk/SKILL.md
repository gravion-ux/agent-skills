# Resolve a project risk by confirming exposure, selecting a response, and verifying mitigation

## Purpose

Resolve a project risk by confirming exposure, selecting a response, and verifying mitigation.

## When to use

Use when the user needs to reduce a specific risk that threatens a project outcome.

## When NOT to use

Do not use this for the technical design of the work; use architecture-design instead.

## Inputs required

- The goal, deadline and constraints
- The people and their capacity
- The dependencies outside the team's control

## Procedure

1. Describe the risk event, cause, impact, trigger, and accountable owner.
2. Estimate probability, impact, and urgency using available evidence.
3. Select avoidance, mitigation, transfer, or acceptance with a rationale.
4. Assign mitigation actions, deadlines, and early-warning indicators.
5. Verify residual exposure and update the project risk register.

## Output contract

A plan with milestones, owners, dependencies, risks and a status view that stays true.

## Validation checklist

- [ ] Every task has one owner
- [ ] Dependencies and blockers are visible
- [ ] The plan reflects actual status, not the original estimate

## Safety notes

Never report progress that is not backed by delivered work.
