# Run a sprint review using delivered increments, acceptance evidence, stakeholder feedback, and next priorities

## Purpose

Run a sprint review using delivered increments, acceptance evidence, stakeholder feedback, and next priorities.

## When to use

Use when the user needs to demonstrate sprint outcomes and gather stakeholder feedback.

## When NOT to use

Do not use this for the technical design of the work; use architecture-design instead.

## Inputs required

- The goal, deadline and constraints
- The people and their capacity
- The dependencies outside the team's control

## Procedure

1. Collect each completed item's acceptance evidence and demonstrated output.
2. Hold the review against the sprint goal and publish a truthful outcome summary.
3. Record stakeholder feedback, defects, and requests without adding scope automatically.
4. Link accepted feedback to backlog items and assign owners for follow-up.
5. Publish the demonstrated result and the next backlog priorities.

## Output contract

A plan with milestones, owners, dependencies, risks and a status view that stays true.

## Validation checklist

- [ ] Every task has one owner
- [ ] Dependencies and blockers are visible
- [ ] The plan reflects actual status, not the original estimate

## Safety notes

Never report progress that is not backed by delivered work.
