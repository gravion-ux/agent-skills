# Estimate a task with story points by comparing scope, complexity, uncertainty, and team calibration

## Purpose

Estimate a task with story points by comparing scope, complexity, uncertainty, and team calibration.

## When to use

Use when the user needs a relative estimate for a backlog task before committing to it.

## When NOT to use

Do not use this for the technical design of the work; use architecture-design instead.

## Inputs required

- The goal, deadline and constraints
- The people and their capacity
- The dependencies outside the team's control

## Procedure

1. Write the task's user outcome and explicit acceptance criteria.
2. Identify workflow, integration, data, and testing complexity.
3. Compare the task with anchored examples from the same team's backlog.
4. Assign the closest calibrated point value and record any uncertainty.
5. Revisit the estimate if new facts materially change the comparison.

## Output contract

A plan with milestones, owners, dependencies, risks and a status view that stays true.

## Validation checklist

- [ ] Every task has one owner
- [ ] Dependencies and blockers are visible
- [ ] The plan reflects actual status, not the original estimate

## Safety notes

Never report progress that is not backed by delivered work.
