# Design a dark-mode variant that preserves hierarchy, legibility, and brand intent

## Purpose

Design a dark-mode variant that preserves hierarchy, legibility, and brand intent.

## When to use

Use when the user needs to adapt an existing visual system to dark appearance.

## When NOT to use

Do not use this for the visual asset itself; use image-visual instead.

## Inputs required

- The user problem and the success criteria
- The platform and the accessibility target
- The existing design system

## Procedure

1. Audit semantic colours, shadows, image assets, and status indicators.
2. Map surface, text, border, and action roles to dark-theme tokens.
3. Check contrast and focus visibility against every dark surface.
4. Adjust elevation, imagery, and chart palettes so hierarchy survives.
5. Compare both themes for equivalent meaning and system-level consistency.

## Output contract

A design specification with flows, states, tokens and the accessibility notes attached.

## Validation checklist

- [ ] Every state is specified, including empty and error
- [ ] Contrast and focus order are defined
- [ ] The design reuses existing tokens

## Safety notes

Never collect personal data in a flow without a stated purpose and consent point.
