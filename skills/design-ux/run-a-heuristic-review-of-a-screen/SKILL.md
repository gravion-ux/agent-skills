# Run a heuristic screen review and document concrete findings with severity and evidence

## Purpose

Run a heuristic screen review and document concrete findings with severity and evidence.

## When to use

Use when the user wants an expert critique of an existing interface.

## When NOT to use

Do not use this for the visual asset itself; use image-visual instead.

## Inputs required

- The user problem and the success criteria
- The platform and the accessibility target
- The existing design system

## Procedure

1. Select the relevant heuristics and define the task and screen boundaries.
2. Inspect visibility, match, control, consistency, prevention, and recovery.
3. Record each finding with location, impact, evidence, and recommendation.
4. Avoid severity claims based only on personal preference.
5. Separate critical usability issues from polish suggestions.

## Output contract

A design specification with flows, states, tokens and the accessibility notes attached.

## Validation checklist

- [ ] Every state is specified, including empty and error
- [ ] Contrast and focus order are defined
- [ ] The design reuses existing tokens

## Safety notes

Never collect personal data in a flow without a stated purpose and consent point.
