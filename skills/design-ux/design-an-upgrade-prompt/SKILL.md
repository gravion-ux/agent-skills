# Design an upgrade prompt that explains the value, limits, and next action without pressure

## Purpose

Design an upgrade prompt that explains the value, limits, and next action without pressure.

## When to use

Use when the user needs to prompt users at a meaningful product limit or feature boundary.

## When NOT to use

Do not use this for the visual asset itself; use image-visual instead.

## Inputs required

- The user problem and the success criteria
- The platform and the accessibility target
- The existing design system

## Procedure

1. Identify the user intent that reached the plan or quota limit.
2. Explain the available action, its benefit, price, and renewal terms plainly.
3. Preserve current work and state exactly what will remain available.
4. Offer a comparison, a clear decline path, and a support route.
5. Confirm consent before any billing change and test the full upgrade path.

## Output contract

A design specification with flows, states, tokens and the accessibility notes attached.

## Validation checklist

- [ ] Every state is specified, including empty and error
- [ ] Contrast and focus order are defined
- [ ] The design reuses existing tokens

## Safety notes

Never collect personal data in a flow without a stated purpose and consent point.
