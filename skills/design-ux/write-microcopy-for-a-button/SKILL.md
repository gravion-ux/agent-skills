# Write button microcopy that names the action and sets a truthful expectation

## Purpose

Write button microcopy that names the action and sets a truthful expectation.

## When to use

Use when the user needs concise labels for a specific interface action.

## When NOT to use

Do not use this for the visual asset itself; use image-visual instead.

## Inputs required

- The user problem and the success criteria
- The platform and the accessibility target
- The existing design system

## Procedure

1. Identify the action's object, verb, and resulting state.
2. Choose a short label that begins with a specific verb.
3. Avoid vague labels such as OK, Yes, or Submit without context.
4. Verify that the wording matches the confirmation or next screen.
5. Check the label beside an icon or assistive name for clarity.

## Output contract

A design specification with flows, states, tokens and the accessibility notes attached.

## Validation checklist

- [ ] Every state is specified, including empty and error
- [ ] Contrast and focus order are defined
- [ ] The design reuses existing tokens

## Safety notes

Never collect personal data in a flow without a stated purpose and consent point.
