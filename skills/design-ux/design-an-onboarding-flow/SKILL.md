# Design an onboarding flow that teaches the core task while minimizing premature requests

## Purpose

Design an onboarding flow that teaches the core task while minimizing premature requests.

## When to use

Use when the user needs a first-run journey that creates value before asking for commitment.

## When NOT to use

Do not use this for the visual asset itself; use image-visual instead.

## Inputs required

- The user problem and the success criteria
- The platform and the accessibility target
- The existing design system

## Procedure

1. Define the activation outcome and the smallest path to reach it.
2. Sequence one teaching action per step with visible progress.
3. Delay optional profile data until its purpose is stated and consent is explicit.
4. Provide skip, back, save, and resume paths where appropriate.
5. Test comprehension, time to value, and completion on small screens.

## Output contract

A design specification with flows, states, tokens and the accessibility notes attached.

## Validation checklist

- [ ] Every state is specified, including empty and error
- [ ] Contrast and focus order are defined
- [ ] The design reuses existing tokens

## Safety notes

Never collect personal data in a flow without a stated purpose and consent point.
