# Design a form that reduces friction while capturing only data needed for its purpose

## Purpose

Design a form that reduces friction while capturing only data needed for its purpose.

## When to use

Use when the user wants a form design that improves completion without deceptive pressure.

## When NOT to use

Do not use this for the visual asset itself; use image-visual instead.

## Inputs required

- The user problem and the success criteria
- The platform and the accessibility target
- The existing design system

## Procedure

1. Map each field to the decision it supports and mark optional fields.
2. Order fields from low-effort to high-commitment inputs.
3. Explain why sensitive data is collected and place consent before submission.
4. Specify inline validation, error recovery, and save-and-resume behavior.
5. Test task completion, abandonment, and accessibility requirements.

## Output contract

A design specification with flows, states, tokens and the accessibility notes attached.

## Validation checklist

- [ ] Every state is specified, including empty and error
- [ ] Contrast and focus order are defined
- [ ] The design reuses existing tokens

## Safety notes

Never collect personal data in a flow without a stated purpose and consent point.
