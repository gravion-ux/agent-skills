# Design an app navigation model that reveals hierarchy without hiding core tasks

## Purpose

Design an app navigation model that reveals hierarchy without hiding core tasks.

## When to use

Use when the user needs to structure navigation for a multi-section application.

## When NOT to use

Do not use this for the visual asset itself; use image-visual instead.

## Inputs required

- The user problem and the success criteria
- The platform and the accessibility target
- The existing design system

## Procedure

1. Group content and tasks by the user's mental model and frequency.
2. Choose primary, secondary, and contextual navigation patterns.
3. Define labels, destinations, hierarchy, and active-state behavior.
4. Specify back, breadcrumb, deep-link, and mobile navigation rules.
5. Test orientation on common tasks and check focus order between regions.

## Output contract

A design specification with flows, states, tokens and the accessibility notes attached.

## Validation checklist

- [ ] Every state is specified, including empty and error
- [ ] Contrast and focus order are defined
- [ ] The design reuses existing tokens

## Safety notes

Never collect personal data in a flow without a stated purpose and consent point.
