# Design reusable card and list patterns with clear hierarchy, actions, and responsive behavior

## Purpose

Design reusable card and list patterns with clear hierarchy, actions, and responsive behavior.

## When to use

Use when the user needs a consistent component for browsing repeated content items.

## When NOT to use

Do not use this for the visual asset itself; use image-visual instead.

## Inputs required

- The user problem and the success criteria
- The platform and the accessibility target
- The existing design system

## Procedure

1. Define the content priority, metadata, status, and action for each item.
2. Specify card anatomy, spacing, dividers, and thumbnail handling.
3. Choose list density modes for scanning versus detailed comparison.
4. Define responsive behavior for narrow and wide viewports.
5. Check keyboard order, hover and focus states, and long-content limits.

## Output contract

A design specification with flows, states, tokens and the accessibility notes attached.

## Validation checklist

- [ ] Every state is specified, including empty and error
- [ ] Contrast and focus order are defined
- [ ] The design reuses existing tokens

## Safety notes

Never collect personal data in a flow without a stated purpose and consent point.
