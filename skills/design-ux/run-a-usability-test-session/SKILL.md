# Run a usability test session while keeping the participant in control and observations unbiased

## Purpose

Run a usability test session while keeping the participant in control and observations unbiased.

## When to use

Use when the user is moderating a live usability test of a product or prototype.

## When NOT to use

Do not use this for the visual asset itself; use image-visual instead.

## Inputs required

- The user problem and the success criteria
- The platform and the accessibility target
- The existing design system

## Procedure

1. Confirm consent, recording preferences, and a no-penalty exit option.
2. Give the task scenario and observe behavior without helping.
3. Ask neutral probes when the participant pauses or comments.
4. Record completion, errors, time, and points of hesitation.
5. Debrief the participant and close the session promptly.

## Output contract

A design specification with flows, states, tokens and the accessibility notes attached.

## Validation checklist

- [ ] Every state is specified, including empty and error
- [ ] Contrast and focus order are defined
- [ ] The design reuses existing tokens

## Safety notes

Never collect personal data in a flow without a stated purpose and consent point.
