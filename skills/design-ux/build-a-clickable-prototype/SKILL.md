# Build a clickable prototype that tests the riskiest interaction assumptions

## Purpose

Build a clickable prototype that tests the riskiest interaction assumptions.

## When to use

Use when the user needs to validate interaction behavior before engineering implementation.

## When NOT to use

Do not use this for the visual asset itself; use image-visual instead.

## Inputs required

- The user problem and the success criteria
- The platform and the accessibility target
- The existing design system

## Procedure

1. Choose the core interaction with the highest product risk.
2. Link the minimum screens needed to complete the primary task.
3. Define feedback for hover, focus, loading, error, and success states.
4. Annotate keyboard behavior, focus movement, and consent points.
5. Run the prototype task and record where participants hesitate.

## Output contract

A design specification with flows, states, tokens and the accessibility notes attached.

## Validation checklist

- [ ] Every state is specified, including empty and error
- [ ] Contrast and focus order are defined
- [ ] The design reuses existing tokens

## Safety notes

Never collect personal data in a flow without a stated purpose and consent point.
