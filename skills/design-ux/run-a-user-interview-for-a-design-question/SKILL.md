# Run a focused interview that turns one design question into actionable evidence

## Purpose

Run a focused interview that turns one design question into actionable evidence.

## When to use

Use when the user needs evidence to answer a specific design question.

## When NOT to use

Do not use this for the visual asset itself; use image-visual instead.

## Inputs required

- The user problem and the success criteria
- The platform and the accessibility target
- The existing design system

## Procedure

1. Write one decision-focused design question and define the evidence needed to answer it.
2. Recruit participants who recently performed the relevant behavior.
3. Ask open questions in a neutral order without pitching solutions.
4. Record observations, quotes, and contradictions with de-identified notes.
5. Synthesize patterns against the success criteria and state confidence limits.

## Output contract

A design specification with flows, states, tokens and the accessibility notes attached.

## Validation checklist

- [ ] Every state is specified, including empty and error
- [ ] Contrast and focus order are defined
- [ ] The design reuses existing tokens

## Safety notes

Never collect personal data in a flow without a stated purpose and consent point.
