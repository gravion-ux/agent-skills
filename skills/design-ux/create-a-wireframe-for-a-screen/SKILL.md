# Create a low-fidelity wireframe that fixes hierarchy, content, and interaction structure

## Purpose

Create a low-fidelity wireframe that fixes hierarchy, content, and interaction structure.

## When to use

Use when the user needs to validate a screen layout before detailed visual design.

## When NOT to use

Do not use this for the visual asset itself; use image-visual instead.

## Inputs required

- The user problem and the success criteria
- The platform and the accessibility target
- The existing design system

## Procedure

1. List the screen's primary action, supporting content, and navigation.
2. Map content into a grid using existing layout constraints.
3. Represent loading, empty, error, and success states as variants.
4. Add labels, focus order, and accessible-name notes to interactive elements.
5. Review the wireframe against the task's success criteria.

## Output contract

A design specification with flows, states, tokens and the accessibility notes attached.

## Validation checklist

- [ ] Every state is specified, including empty and error
- [ ] Contrast and focus order are defined
- [ ] The design reuses existing tokens

## Safety notes

Never collect personal data in a flow without a stated purpose and consent point.
