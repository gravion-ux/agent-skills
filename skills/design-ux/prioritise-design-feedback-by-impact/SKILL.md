# Prioritize design feedback by user impact, evidence strength, reach, and confidence

## Purpose

Prioritize design feedback by user impact, evidence strength, reach, and confidence.

## When to use

Use when the user needs to decide which design feedback to address first.

## When NOT to use

Do not use this for the visual asset itself; use image-visual instead.

## Inputs required

- The user problem and the success criteria
- The platform and the accessibility target
- The existing design system

## Procedure

1. Collect feedback with its source, affected users, and supporting evidence.
2. Score impact, reach, confidence, and implementation effort on a shared scale.
3. Compare scores without letting the loudest request dominate.
4. Group duplicate issues and identify dependencies between fixes.
5. Publish the ranked queue with rationale and explicit deferrals.

## Output contract

A design specification with flows, states, tokens and the accessibility notes attached.

## Validation checklist

- [ ] Every state is specified, including empty and error
- [ ] Contrast and focus order are defined
- [ ] The design reuses existing tokens

## Safety notes

Never collect personal data in a flow without a stated purpose and consent point.
