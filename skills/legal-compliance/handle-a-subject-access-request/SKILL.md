# Handle a subject access request by finding the data, verifying the identity and meeting the deadline

## Purpose

Handle a subject access request by finding the data, verifying the identity and meeting the deadline.

## When to use

Use when the user has received a request from a person asking for their personal data.

## When NOT to use

Do not use this for a routine internal policy note; use documentation instead.

## Inputs required

- The document, process or data in scope
- The jurisdiction and the obligations
- The deadline and the risk of non-compliance

## Procedure

1. Record the date the request arrived and start the statutory clock.
2. Verify the identity of the requester before disclosing anything.
3. Search every system that holds data about the person, including the backups and the processors.
4. Assemble the data in a readable format and redact the third-party information properly.
5. Respond within the deadline and record what was sent, when and by whom.

## Output contract

A review with the obligations mapped, the gaps listed and a recommendation per gap.

## Validation checklist

- [ ] Every requirement is traced to a source clause
- [ ] Gaps are ranked by severity
- [ ] The output states that it is not legal advice

## Safety notes

Never present the output as legal advice, and never sign, file or publish on the user's behalf.
