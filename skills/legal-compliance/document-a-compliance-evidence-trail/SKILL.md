# Document a compliance evidence trail so any control can be proved on demand

## Purpose

Document a compliance evidence trail so any control can be proved on demand.

## When to use

Use when the user wants to be able to show that a control is actually operating.

## When NOT to use

Do not use this for a routine internal policy note; use documentation instead.

## Inputs required

- The document, process or data in scope
- The jurisdiction and the obligations
- The deadline and the risk of non-compliance

## Procedure

1. Name the control and the requirement it satisfies.
2. Define what evidence counts, such as a log, a sign-off or a configuration export.
3. Set how often the evidence is collected and who reviews it.
4. Store the evidence where it can be found by someone who was not there.
5. Test the trail by asking a colleague to retrieve one piece of evidence unaided.

## Output contract

A review with the obligations mapped, the gaps listed and a recommendation per gap.

## Validation checklist

- [ ] Every requirement is traced to a source clause
- [ ] Gaps are ranked by severity
- [ ] The output states that it is not legal advice

## Safety notes

Never present the output as legal advice, and never sign, file or publish on the user's behalf.
