# Plan a one-week developer onboarding path that reaches a verified contribution without hidden setup steps

## Purpose

Plan a one-week developer onboarding path that reaches a verified contribution without hidden setup steps.

## When to use

Use when the user wants a new developer to contribute meaningfully within one week.

## When NOT to use

Do not use this for a one-off local script; use software-engineering instead.

## Inputs required

- The recurring friction the team hits
- Who experiences it and how often
- The tooling already in place

## Procedure

1. Map day-one access, environment setup, architecture context, and the team's current priorities.
2. Assign a small scoped task with a reviewer and a visible definition of done.
3. Pair the new developer for setup, code reading, and the first review.
4. Schedule a midweek blocker review and reserve time for feedback near week's end.
5. Measure onboarding completion, first contribution status, and remaining setup gaps.

## Output contract

A working tool, template or command plus the documentation and adoption note.

## Validation checklist

- [ ] The friction is measured before and after
- [ ] The new path is documented and discoverable
- [ ] It does not add a step to the critical path

## Safety notes

Never change a shared default that silently affects every developer without a migration note.
