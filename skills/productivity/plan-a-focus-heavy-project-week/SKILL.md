# Shape a project week around protected focus time with dependencies and slack ordered

## Purpose

Shape a project week around protected focus time with dependencies and slack ordered.

## When to use

Use when the user needs to advance one demanding project across a constrained week.

## When NOT to use

Do not use this for a shared team workflow; use project-management instead.

## Inputs required

- The tasks or commitments in scope
- The time and attention available
- The deadline or habit being targeted

## Procedure

1. List the project's remaining pieces and mark their dependencies.
2. Estimate the focus hours each piece needs and total them for the week.
3. Schedule the largest focus block on the best available morning.
4. Place the dependent pieces in later blocks only after their inputs land.
5. Hold back one block as slack for review, rework or an overrun.
6. Keep an evening or weekend period free of project work.

## Output contract

A prioritised, time-boxed plan with the next concrete action stated.

## Validation checklist

- [ ] The first action can start immediately
- [ ] The plan fits the available time
- [ ] Each item has an explicit done condition

## Safety notes

Never schedule rest, health or recovery time away to fit more work in.
