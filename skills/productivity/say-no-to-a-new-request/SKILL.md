# Decline a new request with a clear reason and, when possible, a smaller alternative

## Purpose

Decline a new request with a clear reason and, when possible, a smaller alternative.

## When to use

Use when the user has been asked for more work and wants to refuse or redirect it.

## When NOT to use

Do not use this for a shared team workflow; use project-management instead.

## Inputs required

- The tasks or commitments in scope
- The time and attention available
- The deadline or habit being targeted

## Procedure

1. Read the request and note the time it would realistically consume.
2. Check it against the current commitments already on the calendar.
3. Choose a decline, a redirect or a smaller scope with a named limit.
4. Write a short reply stating the decision and, if relevant, the alternative.
5. Send the reply and add any accepted work to the task list with a due date.

## Output contract

A prioritised, time-boxed plan with the next concrete action stated.

## Validation checklist

- [ ] The first action can start immediately
- [ ] The plan fits the available time
- [ ] Each item has an explicit done condition

## Safety notes

Never schedule rest, health or recovery time away to fit more work in.
