# Group pending tasks by location, tool or energy need so batches can run without switching

## Purpose

Group pending tasks by location, tool or energy need so batches can run without switching.

## When to use

Use when the user wants pending tasks sorted into batches that avoid constant context switching.

## When NOT to use

Do not use this for a shared team workflow; use project-management instead.

## Inputs required

- The tasks or commitments in scope
- The time and attention available
- The deadline or habit being targeted

## Procedure

1. Write each pending task on one line with its required context.
2. Name the contexts, such as laptop, phone, home desk or errand.
3. Create one group per context and move every matching task into it.
4. Order groups by how often they can be completed in a single sitting.
5. Give each group a time estimate and a target completion date.

## Output contract

A prioritised, time-boxed plan with the next concrete action stated.

## Validation checklist

- [ ] The first action can start immediately
- [ ] The plan fits the available time
- [ ] Each item has an explicit done condition

## Safety notes

Never schedule rest, health or recovery time away to fit more work in.
