# Write an abstract that states the problem, the method, the result and the significance

## Purpose

Write an abstract that states the problem, the method, the result and the significance.

## When to use

Use when the user needs a short summary of a technical piece of work.

## When NOT to use

Do not use this for a reference-manual API listing; use api-design instead.

## Inputs required

- The technical subject and the reader's level
- The decision the reader must make
- The evidence and examples available

## Procedure

1. State the problem the work addresses, in one sentence.
2. Name the method or approach in one sentence.
3. Give the main result with the number that matters.
4. State the significance, which is what a reader should now do differently.
5. Keep it within the length limit and remove anything that does not serve those four points.

## Output contract

A precise technical document with a clear structure, correct terminology and verified examples.

## Validation checklist

- [ ] The terminology is consistent throughout
- [ ] Every instruction was followed once end to end
- [ ] The document states its assumptions

## Safety notes

Never state a performance, security or compatibility claim that was not verified.
