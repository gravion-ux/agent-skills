# Write a technical slide deck where each slide makes one point that the audience can read

## Purpose

Write a technical slide deck where each slide makes one point that the audience can read.

## When to use

Use when the user needs to present technical material as slides.

## When NOT to use

Do not use this for a reference-manual API listing; use api-design instead.

## Inputs required

- The technical subject and the reader's level
- The decision the reader must make
- The evidence and examples available

## Procedure

1. Write the one point each slide makes before writing any of the slide content.
2. Put the conclusion in the title, so the audience can follow the argument from the slide list.
3. Keep the body to the evidence for that point and remove the rest.
4. Split any slide that needs more than one idea into two slides.
5. Write the notes that carry the detail the slide cannot hold.

## Output contract

A precise technical document with a clear structure, correct terminology and verified examples.

## Validation checklist

- [ ] The terminology is consistent throughout
- [ ] Every instruction was followed once end to end
- [ ] The document states its assumptions

## Safety notes

Never state a performance, security or compatibility claim that was not verified.
