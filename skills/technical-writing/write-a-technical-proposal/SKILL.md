# Write a technical proposal that states the problem, the options and the recommendation

## Purpose

Write a technical proposal that states the problem, the options and the recommendation.

## When to use

Use when the user wants to propose a technical course of action for approval.

## When NOT to use

Do not use this for a reference-manual API listing; use api-design instead.

## Inputs required

- The technical subject and the reader's level
- The decision the reader must make
- The evidence and examples available

## Procedure

1. Describe the problem and its current cost in measurable terms.
2. State the constraints that any solution must respect.
3. Present the options with their costs and their risks.
4. Recommend one option and explain the reasoning.
5. Define the work, the people and the first milestone.

## Output contract

A precise technical document with a clear structure, correct terminology and verified examples.

## Validation checklist

- [ ] The terminology is consistent throughout
- [ ] Every instruction was followed once end to end
- [ ] The document states its assumptions

## Safety notes

Never state a performance, security or compatibility claim that was not verified.
