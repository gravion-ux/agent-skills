# Edit a document for clarity by cutting what the reader does not need and ordering what they do

## Purpose

Edit a document for clarity by cutting what the reader does not need and ordering what they do.

## When to use

Use when the user has a draft that is correct but hard to follow.

## When NOT to use

Do not use this for a reference-manual API listing; use api-design instead.

## Inputs required

- The technical subject and the reader's level
- The decision the reader must make
- The evidence and examples available

## Procedure

1. List the decisions the reader must be able to make after reading.
2. Move everything that does not serve a decision to an appendix.
3. Replace long sentences with shorter ones and cut the adverbs.
4. Make the headings say what the section contains rather than what it is about.
5. Read it aloud and fix the places where the rhythm breaks.

## Output contract

A precise technical document with a clear structure, correct terminology and verified examples.

## Validation checklist

- [ ] The terminology is consistent throughout
- [ ] Every instruction was followed once end to end
- [ ] The document states its assumptions

## Safety notes

Never state a performance, security or compatibility claim that was not verified.
