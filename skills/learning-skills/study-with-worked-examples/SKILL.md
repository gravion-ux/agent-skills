# Study with worked examples by analysing fully solved problems first, then fading the support through completion problems until the learner solves unaided

## Purpose

Study with worked examples by analysing fully solved problems first, then fading the support through completion problems until the learner solves unaided.

## When to use

Use when the user is learning a procedural skill — maths, programming, a language pattern — and keeps failing problems they have only read about.

## When NOT to use

Do not use this for producing a training artefact for a team; use technical-writing instead.

## Inputs required

- The learner's level and goal
- The time available
- The practice or assessment that proves learning

## Procedure

1. Choose worked examples that cover the problem types the learner must master, one type at a time.
2. Study each example by explaining every step aloud or in writing before moving on, naming why that step was chosen.
3. Cover the solution and reconstruct it from memory, checking each step against the original only after a genuine attempt.
4. Move to completion problems where the first steps are given and the learner supplies the rest, reducing the given steps as accuracy improves.
5. Attempt a full unaided problem of the same type and compare the result against a worked example, not just an answer key.
6. Log every step where the reconstruction failed and add one more worked example for exactly that step before progressing.

## Output contract

A study plan with exercises, a checkpoint schedule and a self-test.

## Validation checklist

- [ ] The plan has a measurable outcome
- [ ] Practice starts before the reading ends
- [ ] There is a way to check retention

## Safety notes

Never present unverified claims about a topic as established fact.
